# 第 0 章 引言

## 0.1 一页摘要（业务语言）

第一版（V1）聚焦核心知识库能力（入库、清洗、检索、问答、图谱、溯源），在**可信内网、内置单管理员**的边界内运行。第二版（V2）在企业真正多部门、多系统使用时补齐三块**接入治理能力**：**① 认证与权限**——员工用企业账号登录，不同部门的人只能检索各自有权限的知识库；**② API 网关**——统一入口的限流、熔断与流量治理，支撑规模化访问；**③ 开放 API**——把"问知识库"能力以标准接口开放给企业内其他系统（客服、OA、门户），带独立密钥与配额计量。

本文档同时给出**V1→V2 回补改造清单**（第 5 章）：V1 在数据表、检索接口、缓存键上预留的扩展点，保证 V2 引入权限时**不重构、只启用**。

## 0.2 目的与范围

定义 V2 扩展功能的需求与设计要点。V2 不重复 V1 内容（见 WL2-DOC-001 v1.1 / WL2-DOC-002 v1.1）。

## 0.4 术语表（V1 术语见 WL2-DOC-001 §0.5）

| 术语 | 解释 |
|---|---|
| JWT | 无状态令牌认证：登录后签发访问令牌，服务端验签无需存会话 |
| RBAC | 基于角色的访问控制：用户→角色→权限三层映射 |
| OAuth2 / LDAP / SSO | 企业统一认证的常见协议：授权码模式 / 目录服务 / 单点登录 |
| API Key | 供程序调用开放 API 的长期密钥，独立于用户账号计量限流 |
| API 网关 | 统一入口层：鉴权、限流、熔断、路由、灰度 |
| 多租户 | 组织/部门级硬隔离：各租户数据与可见范围互不可见 |

# 1 V2 定位与范围

**定位**：V1 = 核心知识库引擎（可信边界内运行）；V2 = 接入治理层（认证授权、网关、开放能力、多租户）。

**范围（In）**：认证与 RBAC（含 SSO/LDAP 对接）、检索权限过滤、API 网关能力、开放 API 与 API Key、多租户组织隔离（原附录 B-1 议题随 V2 落地）。

**不做（Out）**：移动原生 App、实时协同编辑等仍按 WL2-DOC-001 §4.4 Won't/延后登记处理，不随 V2 自动升版。

**触发条件（建议，待确认）**：满足任一即启动 V2——① 使用者超出单一可信团队（≥2 个部门/≥50 人）；② 需要按知识库区分"谁能看"；③ 有第三方系统要集成问答能力；④ 平台暴露到非可信网段。

# 2 功能需求

> 编号沿用全局 ID 体系：FR-101/108/125/156 自 V1 v1.0 迁入（内容微调），FR-119/160 为 V2 新增。

## 2.1 认证与权限（迁移 + 扩展）

**FR-101 用户认证与 RBAC 权限**【自 V1 v1.0 迁入，V2 范围】
- 描述：账号密码登录（JWT 访问+刷新令牌，可撤销）；用户—角色—权限三级模型；平台级角色（系统管理员/审计员/普通用户）与知识库级角色（管理员/编辑者/查看者）双层控制；企业统一认证对接（原 FR-156【并入】：OAuth2/LDAP/SSO，按企业身份平台协议选型）。
- 触发场景：SC-001/SC-006（V2）——不同员工可见知识范围不同。
- 不做的代价：V1 只能靠网络边界整体保护，部门间知识无法分权，跨部门推广受阻。
- 验收准则提示：越权访问（横向/纵向）用例全拒；权限变更 ≤1 分钟生效（含检索过滤）；SSO 对接按协议用例通过。

**FR-108 检索权限过滤（数据行级隔离）**【自 V1 v1.0 迁入，V2 范围】
- 描述：检索与问答在召回阶段按用户可见知识库过滤（向量库标量过滤下推）；被过滤内容对模型完全不可见。
- 触发场景：SC-001/SC-006（V2）。
- 不做的代价：越权者可通过问答套出无权限内容——V2 上线门禁红线。
- 验收准则提示：构造"无权限知识库含唯一正确答案"的对抗用例，回答"未找到"且提示词/日志无泄露痕迹。

## 2.2 开放 API 与网关

**FR-125 OpenAPI 开放接口**【自 V1 v1.0 迁入，V2 范围】
- 描述：问答（含 SSE 流式）、检索、文档入库、图谱查询开放 API；API Key 管理（签发/吊销/独立配额限流）；OpenAPI 3.x 文档自动生成。
- 触发场景：SC-009（V2）——内部 OA/客服系统嵌入"问知识库"。
- 不做的代价：平台能力无法进入其他系统，价值局限于 Web 端。
- 验收准则提示：Key 泄露可即时吊销；配额与计量独立于用户会话。

**FR-119 API 网关与流量治理**【V2 新增】（承接原 SD-301 职责的产品化）
- 描述：统一入口：路由聚合、认证前置（对接 FR-101）、限流（用户级/Key 级/全局）、熔断与降级（联动 WL2-DOC-002 §10.3 降级矩阵）、灰度发布、访问审计埋点。
- 触发场景：SC-008/SC-009（V2）——规模化访问下的稳定性。
- 不做的代价：应用层各自为战做限流，故障时无法统一熔断，开放 API 后流量不可控。
- 验收准则提示：限流阈值触发精确到 Key；熔断联动降级矩阵演练通过。
- 选型建议（待门）：自研薄网关（FastAPI 中间件）vs 复用 APISIX/Nginx/Kong——见附录 B-3。

## 2.3 多租户

**FR-160 多租户组织隔离**【V2 新增，承接 V1 附录 B-1 议题】
- 描述：组织/部门级租户：租户内多知识库；租户间数据（文档/向量/图谱/会话/审计）硬隔离；租户管理员自治成员与库。
- 触发场景：SC-002（V2）——集团多子公司/大部门分治。
- 不做的代价：所有部门共享一个平面，知识治理与责权边界混乱。
- 验收准则提示：跨租户任何查询（含向量、图谱、缓存路径）零返回。

# 4 设计要点（模块与关键机制）

## 4.1 模块（SD-ID 沿用）

| SD-ID | 模块 | 设计要点 |
|---|---|---|
| SD-301【迁入 V2】 | API 网关/接入 | 见 FR-119；限流 Redis 令牌桶（用户/Key/全局三级）；trace-id 注入沿用 V1 约定 |
| SD-302【迁入 V2】 | 认证与权限 | JWT 签发校验、RBAC 模型（平台角色 × 知识库角色双层）、权限快照 Redis 缓存 ≤60s + 变更失效；检索下推表达式生成（对接 SD-311 适配器方言） |
| SD-314【迁入 V2】 | 开放 API | API Key 前缀标识（日志可检索）、哈希存储、独立计量（按 Key/按日）、SSE 透传 |
| SD-317【V2 新增】 | 多租户 | tenant_id 贯穿（V1 已预留字段）；向量库 collection 命名空间按租户前缀划分；缓存键含租户段 |

## 4.2 关键机制

1. **权限下推**：BR-001 在 V2 启用——V1 的检索接口已参数化 filter（`kb_ids` 集合），V2 仅把"用户选定集合"替换为"权限计算集合"，引擎零改动。
2. **语义缓存升级**（语义缓存 V1 未实现、延后至 V2，届时随 V2 一并落地）：缓存键含库集合 hash；升级为"权限 scope hash"（防跨权限命中），键结构不变加一段。
3. **审计升级**：V1 actor 为 `admin/anonymous` 两态；V2 升级为真实用户/角色/Key 三态，表结构只增列。

# 5 V1→V2 回补改造清单（traceability 关键）

| # | V1 预留点（已落地设计） | V2 启用动作 |
|---|---|---|
| 1 | `user` 表极简结构；`kb.tenant_id` 字段预留 | 启用 RBAC 三表（user_role/role/role_perm）与租户模型 |
| 2 | chunk 向量 schema 含 `acl_level` 标量字段（V1 恒 0） | 启用 ACL 过滤下推（FR-108） |
| 3 | 检索接口 filter 参数化（kb_ids 集合） | 替换为权限计算集合（SD-302） |
| 4 | 语义缓存 key 含库集合 hash（语义缓存 V1 未实现，延后至 V2） | 升级权限 scope hash |
| 5 | 审计 actor 两态 | 升级用户/角色/Key |
| 6 | 应用统一入口为 FastAPI（无独立网关） | 前置 SD-301 网关（或 APISIX），路由零迁移 |
| 7 | 出网白名单/密钥加密/TLS/注入防护（V1 已有） | 直接继承，无改造 |
| 8 | 部署边界假设"可信内网" | 解除：可暴露非可信网段（配合网关与认证） |

# 6 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 权限模型过设计（角色爆炸） | 运营复杂 | 双层角色固定 3+3，自定义角色延后 |
| SSO 协议与企业身份平台不匹配 | 对接返工 | 立项前协议调研（附录 B-2） |
| 网关选型失误（自研 vs 复用） | 流量治理能力不足 | 附录 B-3 选型对比过门 |
| V1 数据无权限语义，迁移需回填 ACL | 切换期越权窗口 | 全量默认"仅管理员"，再逐步授权（白名单式开放） |
