# 第 0 章 引言

## 0.1 一页摘要（业务语言）

企业内部的知识散落在共享盘、邮件、聊天记录、个人电脑里，员工找资料靠问人和翻文件夹，效率低且知识随人员流动而流失。**WisdomLink2 是一个企业级智能知识库平台**：企业创建多个**知识库**（如"产品部知识库""HR 制度库"），库内用**多级文件夹**分类组织文档；平台自动"读懂"、**清洗去噪**并建立智能索引（含知识图谱与 QA 问答对）；员工直接用自然语言提问——**高频常见问题命中 QA 问答对秒回标准答案**，其余问题走 AI 检索生成**带引用出处**的回答。

第一版（V1）**聚焦核心知识库能力**：多格式入库 → 数据清洗 → 分片索引 → 混合检索（含图谱关联查找）→ **QA 快速命中 / RAG 问答** → 多级溯源（回答 → 知识片段 → 文档版本 → 原始文件，逐级可点开验证）。平台特点：**① 回答可信**——答案标注引用，高频问题返回统一标准答案，没有依据就明说"没找到"；**② 数据主权可控**——大模型、向量化、重排、向量数据库等全部支持**本地部署**与**远程 API**双模式、后台配置切换，并配套**模型 Token 消耗统计**掌握用量与费用；**③ 不被供应商锁定**——向量库支持 Milvus/Qdrant/pgvector/Elasticsearch/FAISS 等多类型可切换，大模型走 OpenAI 兼容协议可接任意厂商。

**认证与权限、API 网关、开放 API 属于第二版扩展**（WL2-DOC-003）——后续权限分配**以知识库为维度**；V1 在可信内网、内置管理员账号的边界内运行，数据结构与接口已预留扩展点，届时"只启用、不重构"。

## 0.5 术语表

| 术语 | 解释 |
|---|---|
| RAG（检索增强生成） | 先从知识库检索相关内容、再让大模型基于检索结果回答的技术路线，可显著降低"编造答案"的概率 |
| 向量库 / 向量数据库 | 专门存储"语义向量"并支持相似度检索的数据库（如 Milvus、Qdrant、pgvector） |
| Embedding / 向量化 | 把文字转换成一组数字（向量）的过程，语义相近的文字向量距离近 |
| 知识库 | 知识的**权限与运营单元**，可创建多个；后续（V2）权限分配以知识库为维度 |
| 文件夹 | 知识库**内部**的多级分类结构，仅用于组织文档，**不参与权限** |
| QA 问答对 | 人工维护的"标准问题 + 标准答案 + 相似问变体"，命中后直接返回，不走 AI 生成 |
| QA 快速命中 | 提问先匹配 QA 对：归一化精确匹配或向量相似度超阈值即秒回标准答案（借鉴 FastGPT 的 QA 存储思路） |
| Token / Token 消耗统计 | 大模型计费与限流的基本单位（约 0.75 个汉字/0.25 个英文词）；平台按模型/知识库/用途/日期统计用量与费用估算 |
| 数据清洗 | 文档解析后、入库前去除页眉页脚/水印/乱码、规范格式、去除重复内容的处理阶段，只去噪不改语义 |
| 分片 / Chunk（知识分片） | 把长文档切成较小片段再分别索引的做法；本文"分片策略"同时涵盖文档切分与向量库数据分片（见 WL2-DOC-002 §9） |
| 混合检索 | 同时用"语义向量检索"与"关键词（BM25）检索"两路召回再融合，兼顾语义理解与精确匹配 |
| BM25 | 经典关键词相关性打分算法（稀疏检索代表） |
| RRF（倒数排名融合） | 把多路检索结果按排名融合的标准方法 |
| 重排 / Rerank | 用更精细的模型对首轮检索结果二次排序，提高前几条命中率 |
| 知识图谱 | 从文档中抽取"实体—关系—概念"构成的图结构：实体是具体对象，关系是联系，概念是分类与层级（本体） |
| GraphRAG / 图谱关联检索 | 问答时先在图谱中定位实体、沿关系多跳扩展，再回捞关联原文片段参与回答 |
| 多级溯源 | 回答中的引用可逐级下钻：引用编号 → 知识片段（含清洗前后对照）→ 文档版本与位置 → 原始文件预览，每级可验证 |
| LangChain / LangGraph | 主流大模型应用开发框架 / 其上的有状态流程编排框架 |
| OpenAI 兼容 API | 业界事实标准的大模型 HTTP 接口协议，多数国产模型与本地推理引擎均兼容 |
| 本地模式 / 远程模式 | AI 组件部署在企业内网（数据不出边界）/ 调用外部云端 API 的两种形态，支持配置切换 |
| 审计日志 | 记录"谁在什么时间对什么做了什么"的流水记录，供追溯 |
| 召回率 Recall@k | 检索质量指标：前 k 条结果包含正确答案素材的比例 |
| 首 token 延迟 | 用户发出问题到屏幕出现第一个字的耗时 |

# 1 业务背景与现状

## 1.1 业务痛点

1. **知识分散、检索低效**：文档散落在共享盘/OA/邮件/IM/个人电脑；现有全文检索只能匹配关键词，无法理解"同义不同词"的问题，员工平均找一份资料需 10–30 分钟。
2. **高频问题重复作答**：HR/IT/客服每天被问几十遍同样的问题（年假、WiFi、报销），答案口径还可能不一致。
3. **新员工上手慢、专家经验流失**：隐性经验依赖"问老员工"，人员变动即知识断层。
4. **AI 试点碎片化、不可控**：各部门自行试用各类 AI 工具，存在敏感数据外泄、答案无依据、用量与费用不可见的风险。
5. **供应商锁定风险**：已试点方案与单一云厂商/单一模型深度绑定，替换成本高。
6. **知识质量无治理**：文档重复、版本混乱、过期内容无下线机制，扫描件/导出 PDF 充斥页眉页脚水印噪声。

## 1.2 现状

- 已有：共享盘与 OA 文档库（仅关键词检索）、部分部门 Wiki 工具、零散 AI 问答试用。
- 缺失：统一知识库组织（库/文件夹）、语义检索、数据清洗、QA 标准问答、可信 AI 问答（引用+溯源）、组件双模式切换、**用量与费用可见性**。

## 1.3 时机与可行性

RAG 技术栈已成熟（混合检索 + 重排 + 图谱增强 + QA 直答成为业界共识方案，见 §8）；开源生态（LangChain/LangGraph、多种开源向量库、本地推理引擎均提供 OpenAI 兼容端点）使自建可控平台成本可行，借鉴 Dify/RAGFlow/FastGPT 等成熟开源产品可降低需求遗漏风险。

# 2 目标与范围

## 2.1 业务目标

| 目标 ID | 目标 | 说明 |
|---|---|---|
| GOAL-01 | 统一知识入口 | 多知识库 + 文件夹分类 + Wiki + 图谱 + QA 统一在一个平台沉淀与消费 |
| GOAL-02 | 找知识提质提速 | 高频问题 QA 秒回；其余问题语义检索 + 图谱关联 + AI 问答 |
| GOAL-03 | 回答可信可溯源 | 答案必带引用或为受控标准答案（QA）、多级溯源可下钻到原始文件、无依据则拒答 |
| GOAL-04 | 数据主权与合规 | 支持全本地部署；远程调用需白名单授权；**用量与费用透明可控** |
| GOAL-05 | 组件可替换、不被锁定 | LLM/向量库等核心依赖可配置切换，更换组件不改业务代码 |

## 2.2 成功指标（验收口径，基线获取方式见附录 B-13）

| 指标 | 目标值 | 度量方式 |
|---|---|---|
| 检索质量 | Recall@10 ≥ 85%，MRR@10 ≥ 0.60 | 平台内置评测集（FR-124），每知识库 ≥ 50 条标注问答对 |
| 答案引用准确率 | ≥ 85% | 人工抽检：引用确实支撑对应结论的比例（月度 ≥ 100 条） |
| QA 快速命中 | 高频问题（评测集 QA 部分）命中准确率 ≥ 95%，误命中率 ≤ 2%；命中响应 P95 ≤ 200ms（NFR-207） | 平台埋点 + 抽检 |
| 溯源可用率 | 100% 引用可完成四级下钻且一致性校验通过（BR-010） | 抽检 ≥ 200 条引用 |
| 清洗有效性 | 样例集清洗后页眉/页脚/水印残留率 ≤ 2%，正文语义零篡改（BR-009） | 清洗评测样例集 |
| 入库时效 | 文档上传到可被检索 ≤ 10 分钟（P95，≤10MB 文档） | 平台埋点 |
| 找资料效率 | 员工平均找资料时间由 ~30 分钟降至 ≤ 5 分钟 | 上线前后各一次问卷/埋点对比 |
| 系统可用性 | ≥ 99.5%（月度） | 监控统计 |
| 双模式切换 | 配置切换生效 ≤ 5 分钟，不重启、不改代码 | 运维演练验证 |
| 用量透明 | Token 统计与 Provider 返回对账误差 ≤ 5%（BR-012） | 月度对账 |

## 2.3 范围边界

**In Scope（V1）**：**多知识库与文件夹分类管理**、多格式解析、数据清洗、分片索引、Wiki、QA 问答对与快速命中、RAG 问答（多轮/流式/引用/多级溯源）、混合检索与重排、知识图谱（实体/关系/概念）与关联检索、LangGraph 编排、组件双模式配置切换、**模型 Token 消耗统计**、内置管理员管理后台、审计日志、部署与监控。

**Out of Scope（V1 不做，归属见下）**：
- → **V2 扩展**（WL2-DOC-003）：用户认证与 RBAC 权限（**以知识库为维度分配**）、检索权限过滤、API 网关、开放 API/多租户。
- → Won't/延后（§4.4）：通用低代码平台、模型训练/微调、即时通讯与网盘、移动原生 App、实时协同编辑、语音问答、多集群联邦。

# 3 角色与业务场景

## 4.1 Must（V1 必须有）

**FR-102 多知识库与文件夹分类管理**【v1.2 重写】
- 描述：**知识库是唯一的权限与运营单元**（无"空间"层级）：创建/编辑/归档/删除知识库；每库独立的文档集合、文件夹结构、策略三件套（清洗/分片/检索参数）、QA 对、图谱。**库内多级文件夹**（建议上限 5 级，可配）用于分类组织：文件夹增删改、拖拽移动文档、文档多选批量移动；检索范围可细化为"库或库内指定文件夹"（可选过滤条件）。**文件夹不参与权限**——V2 权限分配以知识库为维度（与 WL2-DOC-003 FR-101 对齐），跨文件夹的可见性由库级权限决定。
- 触发场景：SC-002——制度/手册/案例需分门别类运营，权限按库整体授给部门。
- 不做的代价：文档堆平铺不可运营；或引入多余层级概念造成权限歧义。
- 验收准则提示：文件夹树操作正确（移动后归属与检索范围过滤同步）；指定文件夹范围的检索不返回范围外内容；库归档后整体不参与检索。

**FR-103 多格式文档上传与解析**
- 描述：支持 PDF/Word(docx)/Excel/PPT/Markdown/TXT/HTML/图片（OCR）；单文件与批量上传（可指定目标文件夹）；解析产出结构化文本（标题层级、表格、代码块）；Web 拖拽上传。
- 触发场景：SC-002。
- 不做的代价：只能处理纯文本，存量知识无用。
- 验收准则提示：≥10 种典型样例文件解析通过率 ≥ 90%；失败进 SC-010 流程。

**FR-104 文档元数据与状态管理**
- 描述：标题/标签/所属文件夹/来源/作者/生效日期等元数据；文档状态机（BR-008）；列表分页、筛选（按文件夹/标签/状态/时间）、搜索。
- 触发场景：SC-002。
- 不做的代价：文档堆不可运营。
- 验收准则提示：筛选准确；状态流转符合 BR-008 决策表。

**FR-105 知识分片与向量化入库（策略可配置）**
- 描述：入库流水线：解析（FR-103）→ 清洗（FR-115）→ 分片（策略与参数按知识库配置）→ 向量化 → 写入向量库与元数据库；全流程幂等可重跑。
- 触发场景：SC-002。
- 不做的代价：文档不可语义检索，AI 问答无从谈起。
- 验收准则提示：BR-003 口径生效；重复上传不产生重复索引；满足 §2.2 时效。

**FR-106 混合检索与重排**
- 描述：向量（语义）+ BM25（关键词）双路召回，RRF 融合，可选重排取 Top-N；各路参数按知识库可配置；检索接口独立于问答可单独调用（供评测）。
- 触发场景：SC-001。
- 不做的代价：专有名词与口语化问题无法同时命中。
- 验收准则提示：评测集 Recall@10/MRR 达标；专有词/口语化两组用例通过。

**FR-107 RAG 智能问答（多轮、流式、引用溯源）**
- 描述：多轮对话（指代消解）；流式输出（SSE）；回答内嵌引用编号，点击经多级溯源链（FR-118）下钻验证；**QA 通道未命中后进入本链路**（BR-011 优先级）；无依据拒答（BR-004）；LangGraph 编排（详见 WL2-DOC-002 §8.6/图 5-3）。
- 触发场景：SC-001/SC-004/SC-012。
- 不做的代价：平台退化为"搜索框"，回答不可信。
- 验收准则提示：引用编号与检索片段一一对应；拒答符合 BR-004；多轮指代正确解析。

**FR-109 LLM/Embedding/Rerank 双模式配置切换（OpenAI 兼容协议）**
- 描述：三类 AI 能力统一走 Provider 配置：远程（OpenAI 兼容 API）或本地（Ollama/vLLM/LMDeploy/Xinference）；管理后台切换、连接测试、健康探测；API Key 加密存储。
- 触发场景：SC-005。
- 不做的代价：供应商深度绑定；敏感数据被迫出边界。
- 验收准则提示：切换生效 ≤5 分钟不重启；端到端冒烟通过；Key 脱敏。

**FR-110 向量库多类型可配置切换**
- 描述：向量存储统一接口，支持至少 4 种实现可配置切换（建议顺序：Qdrant/Milvus/pgvector/Elasticsearch，FAISS 开发用）；集合管理与数据迁移工具。
- 触发场景：SC-005/SC-011。
- 不做的代价：换向量库=重写检索层。
- 验收准则提示：同一评测集在 ≥2 种向量库下指标偏差 ≤3%；迁移完整性校验通过。

**FR-111 系统管理后台（V1 精简版）**
- 描述：知识库参数（清洗/分片/检索策略模板）、Provider 配置、系统参数、任务与死信处置、**Token 用量看板入口（FR-132）**、运行状态总览、审计查询。（用户/角色管理 → V2）
- 触发场景：SC-005/SC-011。
- 不做的代价：运营靠改库。
- 验收准则提示：管理操作全部审计；配置变更可回滚；管理面由内置管理员守门（B-22）。

**FR-112 审计日志**
- 描述：记录问答（含 QA 命中标记）、文档增删改/清洗规则变更、QA 对变更、配置变更、导入导出；只增；按时间/动作/对象检索；保留 ≥180 天。
- 触发场景：SC-006。
- 不做的代价：内容纠纷与误操作无法溯源。
- 验收准则提示：抽样操作 100% 有审计记录。

**FR-113 异步任务与失败重试**
- 描述：解析/清洗/向量化/图谱抽取/预览转换走异步队列；失败自动重试 ≤3 次后转人工，可见原因；死信隔离；进度可查。
- 触发场景：SC-010。
- 不做的代价：一个坏文件拖垮整批入库。
- 验收准则提示：10% 坏文件注入，90% 正常入库；重试符合 BR-008。

**FR-114 会话管理**
- 描述：会话列表、历史、继续对话、删除、导出（含引用与溯源信息）。
- 触发场景：SC-001/SC-004。
- 不做的代价：多轮场景不可用。
- 验收准则提示：会话持久化完整；导出含引用列表。

**FR-115 知识数据清洗管道**
- 描述：解析后、分片前的清洗：页眉/页脚/页码/水印去除、乱码与特殊字符规范化、全半角与空白规整、重复段落去重、OCR 噪声标记、繁简转换（可选）、敏感信息脱敏（正则规则库）；全程留痕可还原（BR-009）。
- 触发场景：SC-002/SC-013。
- 不做的代价：噪声混入向量库污染检索；或为去噪私改内容失真。
- 验收准则提示：清洗样例集达标；每文档可查看清洗前后 diff；按原文一键重建。

**FR-117 知识图谱关联检索（多跳）**
- 描述：查询实体链接（识别+消歧，含别名/同义词）、多跳关联扩展（默认 1 跳可配 ≤2）、概念扩展（同义词/上下位并入改写）、关联片段回捞（证据链→chunk 并入融合排序）、相关实体/文档推荐；未命中自动跳过。
- 触发场景：SC-007。
- 不做的代价：多跳关系问题无从答起。
- 验收准则提示：两跳样例正确且引用含关系证据；关闭图谱路可对比贡献。

**FR-118 多级溯源链**
- 描述：引用四级下钻：引用编号 → 知识片段（含清洗前后对照）→ 文档版本与位置（页码/标题路径）→ 原始文件（在线预览、高亮、可下载）；图谱引用可下钻三元组与证据边；一致性校验（BR-010）：哈希实时比对，不一致标记警示并禁止作为依据；会话内来源列表可展开。
- 触发场景：SC-001/SC-012。
- 不做的代价：引用是摆设，真实性停留在口头。
- 验收准则提示：抽检 100% 四级可达；篡改触发警示；旧版引用标注"非最新版"。

**FR-121 知识图谱构建：实体、关系、概念**
- 描述：三层内容管理——实体（类型 Schema、别名归一、消歧、合并/拆分）、关系（类型 Schema、证据链回指原文）、概念/本体（is-a 层级、同义词、实体挂接）；Schema 约束自动抽取（候选→人工确认）与手工编辑并存；三元组批量导入/导出（CSV/JSON）。
- 触发场景：SC-007/SC-002。
- 不做的代价：FR-117 无米下锅。
- 验收准则提示：导入导出往返一致；候选/确认流转与证据链完整。

**FR-131 QA 问答对与快速命中**【v1.2 新增，Must】
- 描述：**QA 对管理**：标准问题、标准答案（Markdown 富文本，可附引用文档）、相似问变体（多条）、所属知识库与文件夹、启用/停用、排序权重、批量导入/导出（Excel/CSV）、命中次数与最近命中时间统计；从问答日志**一键沉淀 QA**（高频未命中问题转 QA 对草稿）。**快速命中**（BR-011）：提问先走 QA 通道——归一化后精确匹配（含变体）直接返回；未精确命中则 QA 向量相似度 ≥ 阈值（默认 0.92 可配）命中返回；命中答案显著标注"**标准答案（QA）**"并显示维护时间，同时提供"查看 AI 深度回答"入口（可一键触发完整 RAG）；未命中走正常 RAG 链路。
- 触发场景：SC-014——高频同类问题每天重复回答，等 AI 生成慢且口径漂移。
- 不做的代价：高频问题每次全链路生成（慢、贵、答案不一致）；客服/HR 被重复问题淹没。
- 验收准则提示：BR-011 样例全过；命中响应达 NFR-207；命中答案带 QA 标识与维护时间；QA 对变更后命中即时生效（≤1 分钟）。

**FR-132 模型 Token 消耗统计**【v1.2 新增，Must】
- 描述：**计量**：按模型 × 知识库 × 用途（问答/改写/抽取/嵌入/QA 向量化）× 日期，统计输入/输出 Token、调用次数、错误次数、语义缓存命中节省量（BR-012 口径）；**看板**（管理后台）：趋势图（日/月）、Top 模型/知识库排行、费用估算（模型单价管理面可配）；**明细**：会话级用量（每条回答的 token 消耗在会话详情可见）；导出 CSV；**告警**：日耗上限阈值可配，超出触发通知（FR-143 联动/后台标记）。
- 触发场景：SC-015——按量计费看不到账单明细，异常暴涨无感知。
- 不做的代价：费用黑箱；无法归因"哪个库/哪类用途在烧钱"；本地与远程策略调整无依据。
- 验收准则提示：与 Provider 返回 usage 对账误差 ≤5%（BR-012 正例）；本地估算标注；看板数据可下钻到会话明细。

## 4.5 关键业务规则（可判定化，样例=测试标准答案）

> BR-001（检索权限过滤）、BR-005（配额）整体迁 V2（WL2-DOC-003 §3）。

**BR-002 文档去重规则**：同库内按文件 SHA-256 判重；重复默认拒绝并提示；可选"新建版本"（FR-126）。指纹=原始字节流哈希；跨库不判重。
| 用例 | 输入 | 期望输出 |
|---|---|---|
| 正例 | 同库同内容改名文件 | 拒绝，提示已存在 |
| 反例 | 同库同名不同内容 | 允许（加区分提示） |
| 边界 | "新建版本"传同指纹 | 走版本流程，旧索引下线 |

**BR-003 分片参数口径（默认模板）**：递归分片目标 512 token、重叠 64；表格原子化（超长按行组切并复制表头）；Markdown 标题优先；±20% 容差（结构边界优先）；token 按所选 Embedding 模型 tokenizer 计。
| 用例 | 输入 | 期望输出 |
|---|---|---|
| 正例 | 800 token 连续文本 | 2 片，重叠约 64 |
| 边界 | 300 token 完整表格 | 单独 1 片不被切断 |
| 反例 | 默认模板下切断表格 | 不允许（仅显式"固定分片"策略可） |

**BR-004 引用与拒答规则**：每个事实断言 ≥1 引用且指向实际参与生成的片段（经 FR-118 校验）；相关度均低于阈值（默认 0.30 可配）必须拒答，话术含"未在知识库中找到依据"。相关度=Rerank 分（无重排时用首位向量相似度）。
| 用例 | 输入 | 期望输出 |
|---|---|---|
| 正例 | 库含报销条款并提问 | 结论+引用，可四级下钻 |
| 反例 | 无相关内容 | 拒答话术，无无引用断言 |
| 边界 | 两文档冲突 | 双引用+提示以最新生效文档为准，可下钻核实 |

**BR-006 文档版本号规则**：v1.0 起；元数据修改 +0.1；重传内容 +1.0；仅最新已发布版本参与检索；1 位小数直接累加。
| 用例 | 输入 | 期望输出 |
|---|---|---|
| 正例 | v1.0 改标签 | v1.1，索引不重建 |
| 正例 | v1.1 重传新内容 | v2.0，旧索引下线 |

**BR-007 融合与排序口径**：RRF 分 = Σ 1/(k + rank_i)，k=60；加权默认稠密 0.6/稀疏 0.4（4 位小数）；重排后取 Top-N（默认 5）；图谱回捞为独立一路；并列按 chunk_id 升序稳定排序。
| 用例 | 输入 | 期望输出 |
|---|---|---|
| 正例 | 稠密第 2、稀疏第 1 | 1/62+1/61 ≈ 0.0325 |
| 边界 | 仅一路存活 | 直接用该路排名 |

**BR-008 文档状态机**：`已上传→解析中→清洗中→索引中→已发布`；任一阶段失败重试 ≤3（指数退避）→ 失败待人工；`已发布→已下线`；删除→回收站 30 天→物理删除（级联清理向量/图谱/QA/缓存，NFR-262）；每次流转写审计。

**BR-009 清洗留痕与语义保持规则**：清洗逐条留痕（规则 ID、命中位置、动作）；只允许 remove/normalize/mark 三类动作，不得增改语义；原件永不修改；可 diff 对照、按原文一键重建；规则变更审计并支持受影响文档批量重跑。
| 用例 | 输入 | 期望输出 |
|---|---|---|
| 正例 | 每页页眉"XX 公司机密" | 全移除且留痕，正文零变化 |
| 反例 | 规则误删正文段 | 对照视图可见→标记误伤→可还原重建 |
| 边界 | 表格内含同文本 | 页眉规则不作用于表格区（位置上下文） |

**BR-010 溯源链一致性规则**：chunk 存清洗后哈希+所属版本指纹；溯源时实时比对，不一致→"内容可能已变更"警示并禁止作为依据；四级链路每级可达可验证；旧版引用标注"非最新版"。
| 用例 | 输入 | 期望输出 |
|---|---|---|
| 正例 | 正常下钻 | 四级全通（含清洗对照） |
| 反例 | 篡改库中 chunk | 比对失败→警示，不出示为依据 |
| 边界 | 引用来自旧版本 | 指向旧版原件+标注+最新版入口 |

**BR-011 QA 快速命中与优先级规则**【v1.2 新增】
- 规则：**优先级 QA > 语义缓存 > RAG**；QA 精确命中（问题归一化后与标准问或任一变体全等）优先于相似命中；相似命中需相似度 ≥0.92 且与次高候选分差 ≥0.02（防边界抖动，均可配）；检索范围内多个 QA 命中→取分数最高，同分取排序权重高者、再同取库创建顺序；命中答案必须标注"标准答案（QA）"+所属库+维护时间；命中记录审计并累计命中统计；停用/删除的 QA 对即时退出命中（≤1 分钟）。
- 归一化口径：大小写转小写、全角转半角、连续空白合并、首尾空白与结尾标点（？?。.!！）去除；不做分词级模糊。

| 用例 | 输入 | 期望输出 |
|---|---|---|
| 正例-精确 | QA 标准问"怎么申请年假"，变体含"如何申请年假？"；提问"如何申请年假？" | 归一化全等→精确命中，秒回标准答案（≤NFR-207） |
| 正例-相似 | QA"公司 WiFi 密码是多少"；提问"wifi 密码多少" | 归一化不等→向量相似 0.95 ≥0.92 → 命中，标注 QA |
| 反例 | 提问" WiFi 密码泄露了怎么办"（相似 0.85 且有更优 RAG 结果） | 未达阈值→走 RAG，不误回标准答案 |
| 边界1 | 两 QA 对相似同分 0.93 | 取权重高者；权重同→库创建顺序 tie-break |
| 边界2 | 精确命中但该 QA 已停用 30 秒 | 不命中（即时生效口径 ≤1 分钟） |

**BR-012 Token 统计口径规则**【v1.2 新增】
- 规则：用量以模型 API 返回的 usage 为准（prompt/completion 分计）；本地引擎无返回时按模型 tokenizer 估算并标注"估算"；嵌入按实际向量化的字符/文档数折算 token；统计按 Asia/Shanghai 自然日聚合；费用 = Σ(token/1,000,000 × 单价)，单价管理面配置（默认人民币，保留 2 位小数，四舍五入）；语义缓存/QA 命中不产生生成 token，计为"节省量"单独展示；对账口径：月度平台统计与 Provider 账单误差 ≤5%。
| 用例 | 输入 | 期望输出 |
|---|---|---|
| 正例 | 远程 API 返回 usage 1234/567 | 统计原值，费用按单价计算 |
| 反例 | 本地引擎无 usage | tokenizer 估算 1200/550，标注"估算" |
| 边界 | 23:59 发起 00:01 完成 | 计入完成时刻所在自然日 |
| 边界 | QA 命中直接返回 | 0 生成 token，"节省量"+1 |

# 6 约束

## 6.1 技术栈约束（用户指定）

1. 编排框架：**LangChain + LangGraph**。
2. 业务存储：**MySQL**；缓存/队列/会话：**Redis**。
3. 向量库：**可插拔多类型**（至少适配 Qdrant/Milvus/pgvector/Elasticsearch/FAISS 中的 4 种，本地与托管双形态）。
4. LLM/Embedding/Rerank：**OpenAI 兼容协议**，本地与远程双模式。
5. 检索策略、分片策略、清洗规则、**QA 命中阈值**为平台一等公民：策略与参数配置化。
6. 知识图谱：实体/关系/概念三层 + 图存储 + GraphRAG 关联检索。

## 6.2 双模式约束（跨切红线）

所有外部 AI 依赖（LLM/Embedding/Rerank/向量库/图存储/对象存储/解析与预览转换服务）必须同时具备本地部署与远程服务两种形态，切换仅通过配置完成。任何"只支持云端/只支持本地"的组件引入都违反本约束。

## 6.3 部署与合规约束

- **V1 边界假设**：无认证体系，部署于可信内网/防火墙后；管理面内置管理员守门（NFR-219、B-22）。
- **组织模型约束**【v1.2 新增】：知识库是唯一权限单元（V2 以库维度授权）；文件夹仅分类，不承载权限语义。
- 敏感库可标记"仅本地"强制本地模型；远程出网白名单。
- 开源许可证治理：优先 Apache-2.0/MIT/BSD；SSPL/ELv2/AGPL/GPL 须法务评审披露（R6、B-11）。

## 6.4 项目宪法草案（待确认后存入 memory/constitution.md）

1. 组件可插拔红线：核心依赖必须经 Provider 抽象接入，禁止业务代码直连厂商 SDK。
2. 质量红线：核心链路（入库/清洗/检索/问答/**QA 命中**）单测覆盖率 ≥80%；评测集（含 QA 命中准确率 ≥95%）为发布门禁；溯源四级可达抽检为发布门禁。
3. 安全底线：V1 以部署边界+管理面守门替代权限体系；API Key 不落明文日志；审计只增；清洗不得改变语义内容。
4. 性能硬指标：NFR-201/202/206/**207** 为发布门槛。
5. 文档与协作：文档带 ID 可追溯；基线变更走 C-05；不为先进而先进。

# 8 调研摘要（关键结论 + 来源，详见附录 A）

1. **竞品格局与借鉴**：Dify（生态最全）、RAGFlow（版面级解析最强）、FastGPT（开箱即用企业知识库问答，**QA 拆分存储/混合检索/重排打磨细**——FR-131 QA 快速命中直接借鉴此思路）、LangChain-Chatchat（本地化先驱，趋维护态）。
2. **检索策略**：混合检索（稠密+BM25）+ RRF 是性价比最高的单项升级（实践报告 recall@10 约 65–78%→91%，须自建评测集复测）；cross-encoder 重排末段精排；查询改写按延迟预算选择性启用；**高频问题用 QA 直答是省时省 token 的共识手段**。
3. **分片策略**：固定切分是弱基线（错误策略最高约 9% 召回差距）；父子分片、标题感知、表格原子化是生产主流。
4. **GraphRAG 生产化**：Schema 约束抽取、共指消解与别名归一、KG+向量混合（HybridRAG）——FR-117/121 依据。
5. **向量库**：Milvus（大规模）、Qdrant（低延迟+稀疏）、Weaviate、pgvector（轻量）、ES（BM25+kNN+RRF，ELv2 注意）、FAISS（开发）。可插拔+按规模选型（FR-110）。
6. **双模式可行性**：Ollama/vLLM/LMDeploy/Xinference 均提供 OpenAI 兼容端点，与云端协议同构——一套 Provider 配置覆盖（WL2-DOC-002 §7.3）。
