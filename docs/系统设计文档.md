# WisdomLink2 系统设计文档（正式版 v1.0）

> 基于代码实际状态反向整理，描述系统架构与模块划分。

## 1. 架构概览

**模块化单体**：一个 FastAPI 应用承载全部业务，Vue 3 SPA 前端，通过 JSON API + SSE 访问后端。

```
Vue 3 + TypeScript + Element Plus (前端 SPA)
  ├─ router / views / components
  ├─ Pinia stores
  └─ api/http.ts (axios + SSE fetch/AbortController)
           │ HTTP JSON + text/event-stream
           ▼
FastAPI 模块化单体 (全异步)
  ├─ API 路由层（6 个 Router：kb/documents/qa/chat/kg/admin）
  ├─ 引擎层（engine/：清洗/分片/入库/检索/QA命中/流式编排）
  ├─ Provider 适配层（providers/：LLM/Embedding/Rerank/向量库/图存储/对象存储/解析/预览）
  ├─ 核心层（core/：配置/缓存/规则/安全/计量/日志）
  └─ 中间件（请求日志 + trace-id 注入）
           │
           ├─ MySQL 8（业务事实源，含图谱三表，SQLite 兜底）
           ├─ Redis 7（缓存/队列/会话，不可用时内存兜底）
           ├─ 向量库（可插拔：Qdrant / Milvus / FAISS）
           ├─ 对象存储（本地目录 / MinIO-S3）
           └─ 外部模型（LLM/Embedding/Rerank/OCR，OpenAI 兼容协议，本地或远程）
```

## 2. 技术栈

| 层次 | 选型 | 说明 |
|---|---|---|
| 后端框架 | FastAPI + uvicorn | 全异步、SSE、自动 OpenAPI 文档 |
| 编排 | LangChain + LangGraph | 问答状态机（意图→改写→检索→充分性→生成→引用校验，自纠错≤2轮） |
| 数据库 | SQLAlchemy + MySQL（SQLite 兜底） | 17 张业务表 |
| 缓存/队列 | Redis（内存兜底） | QA 字典/权限快照/配置热更新广播 |
| 向量库 | Qdrant / **Milvus**（生产）/ FAISS（开发） | chunk 集合 + QA 集合物理隔离，HNSW 索引 |
| Rerank | 本地 ONNX（bge-reranker）/ **智谱 API** | sigmoid 归一 / 远程 API，启动预热+加载锁 |
| **OCR** | **Tesseract（本地 Docker）/ GLM-4V-flash（远程）** | **auto 模式逐级回退，中文识别 95%+** |
| **PPT 解析** | **python-pptx** | **标题/正文/表格/备注，页码=幻灯片编号** |
| 前端 | Vue 3 + TypeScript + Element Plus + ECharts | 15 个页面，设计 Token 统一 |
| 图计算 | NetworkX | 多跳扩展、社区检测（模块度聚类） |

## 4. 关键设计决策

| 决策 | 理由 |
|---|---|
| 模块化单体（非微服务） | 单团队交付速度最优；模块边界清晰可按需拆分 |
| 全 Provider 抽象 | 双模式红线：本地/远程切换只改配置不改代码 |
| LangGraph 状态机 | 问答流程需要循环（检索不足重试≤2）、分支（QA/RAG/图谱）、checkpoint |
| generation 原子发布 | 重建期间检索不中断（active=false 暂存→原子切换） |
| QA 双集合隔离 | QA 向量与 chunk 向量物理隔离，防混检误回 |
| Markdown 预览替代 LibreOffice | Office 文档入库时自动转 Markdown（含图片提取），零外部依赖 |
| 真流式（不等整段生成） | 首 token 体感从 5-15s 降到 <2s |

## 5. 数据流

### 5.1 文档入库
```
上传 → SHA-256 判重 → 解析（parse_file）
→ Markdown 预览版生成（含图片提取存对象存储）
→ 清洗（规则链留痕） → 语义分片（类型标签）
→ 新代 chunk active=false 暂存 → 向量化 → 原子切换 active=true
→ 旧代下线 → 状态=已发布
```

### 5.2 问答（真流式）
```
提问 → 多轮上下文注入（最近 4 轮）
→ QA 命中检查（精确→相似）→ 命中即秒回
→ 意图分析 → 查询改写（相关性不足时改写重检索）→ 三路检索（向量+BM25+图谱）
→ RRF 融合 → 重排 → 相关性下限过滤 → 相邻补充
→ SSE 逐 token 转发 → 引用列表 → done
```

### 5.3 组件切换
```
.env 修改 → 重启生效 → 启动横幅打印配置（python路径/模型/向量库/图存储）
→ 首次检索预热（本地重排模型加载）
```

## 6. 安全设计

- V1 边界：可信内网部署；管理面 JWT 守门；问答入口免登录
- 密钥：AES-GCM 加密落库，日志/接口脱敏（尾 4 位）
- 传输：生产全站 TLS
- 审计：只增（append-only），关键操作全覆盖
- 提示注入：数据隔离区注入 + 指令分离标注 + 输出引用校验

## 7. 降级矩阵

| 故障 | 动作 | 用户感知 |
|---|---|---|
| 远程 LLM | 提示切本地 / 降级显示相关片段 | 明确降级提示 |
| 向量库 | 退化 BM25 | "降级模式"标注 |
| Rerank | 跳过精排 | 质量轻微下降（审计记录） |
| Redis | 内存兜底 | 变慢但可用 |
| 图谱路 | 关闭该召回路 | 退化为普通检索 |
| 预览转换 | 降级原件下载 | 提示配置 |

## 8. 部署视图

**最小部署**（Docker Compose）：app + MySQL + Redis + Qdrant + MinIO，可选 Ollama/LibreOffice。

**生产部署**（K8s）：app ×N（HPA）+ worker ×N + MySQL 主从 + Redis 哨兵 + 向量库集群 + Prometheus/Grafana。

**纯本地离线**：SQLite + 内存缓存 + FAISS + 本地模型，零外部依赖。
